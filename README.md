# 毛利 · 粗算面板（profit-script）

电商多平台「粗算毛利」分析应用：从本地 Excel 数据源读取订单、成本、广告消耗与商务订单（达人佣金），按人工费率与判定规则实时汇总各平台毛利，并提供可拖拽的状态判定面板与人工填写面板。

- 前端：Vue 3 + TypeScript + Vite + Pinia + ECharts（自绘主题）
- 服务端：Node + Fastify，流式解析 xlsx（最大单表 1.2GB 也可处理），本地缓存、配置持久化、Excel 导出
- 平台：快手、视频号、抖音、天猫、拼多多、京东、小红书（新增平台自动按文件名识别）
- 数据目录：`excel/`（只读），运行数据：`data/`（配置 + 缓存）；打包版默认使用系统应用数据目录（见「打包与运行」）

## 快速开始

**一键启动**：Windows 双击 [`启动应用.cmd`](启动应用.cmd)，macOS 双击 [`启动应用.command`](启动应用.command)（首次需 `chmod +x 启动应用.command`）。脚本会自动检查 Node、安装依赖、构建前端、启动服务并打开浏览器；详细参数、停止/后台运行与常见问题见 [docs/START.md](docs/START.md)。

命令行方式：

```bash
npm install
npm run dev        # 开发模式：API 8787 + 前端 5173（http://localhost:5173）
# 或者生产模式：
npm run build && npm start   # 单端口 http://127.0.0.1:8787
# 或使用一键脚本（自动安装/构建/打开浏览器）：
node scripts/start-app.mjs            # = Windows 启动应用.cmd / macOS 启动应用.command
node scripts/start-app.mjs --port 8788 --no-open
```

首次启动会流式解析全部订单源（含 837MB 的抖音订单、1.2GB 提成用 Sheet，约 2 分钟），之后走 `data/cache/` 缓存，约 4~5 秒加载。点击右上角「刷新数据」可强制重新解析。

## 打包与运行（macOS / Windows）

当前版本 **v1.2.0**（版本号统一在 `shared/version.ts`，页头、接口与安装包文件名保持一致）。

```bash
npm run package:app       # 构建全部平台：macOS arm64 / macOS x64 / Windows x64
npm run package:app:mac   # 只构建 macOS
npm run package:app:win   # 只构建 Windows
```

产物在 `release/`（每个 zip 内含官方 Node.js 运行时 + 打包后的服务端 + 前端 dist，**不包含 Excel 源文件与缓存**）：

- macOS：`profit-script-v1.2.0-macos-arm64.zip` / `-macos-x64.zip`，解压后先执行一次
  `xattr -dr com.apple.quarantine ProfitScript.app`，再双击 `ProfitScript.app`（或运行 `./profit-script.command`）；
- Windows：`profit-script-v1.2.0-win-x64.zip`，解压后双击 `profit-script.cmd`。

打包版默认数据目录：macOS `~/Library/Application Support/ProfitScript/`、Windows `%APPDATA%\ProfitScript\`：

```
excel/    ← 源文件放这里（订单源/成本表/月消耗表/商务订单），不随安装包分发
data/     ← config.json（人工参数、补录成本、归类）与 cache/（解析缓存）
```

升级时只替换程序目录，保留数据目录即可继续使用原有参数与缓存；也可用 `--home` 或 `PROFIT_SCRIPT_HOME` 指定目录。完整说明见 [docs/PACKAGING.md](docs/PACKAGING.md)。

- 商务订单文件会递归扫描并按「顶层汇总文件优先」去重：快手/视频号按 `平台+订单号+SKU`，抖音按 `平台+订单号`；
- 商务数据中的「团长订单 / 团长服务费」仅记录数量与金额，不计入达人佣金。

## 毛利公式

```
粗算毛利 = 预估结算金额
         − 产品成本（成本单价 × 结算商品数量）
         − 包装费（分平台；按件单价 × 结算商品数量，或直接填写总额）
         − 运费（分平台；按件单价 × 结算商品数量，或直接填写总额）
         − 运费险（分平台；按件单价 × 结算商品数量，或直接填写总额）
         − 平台技术服务费（人工费率 × 预估结算金额，分平台）
         − 商业保险费（人工费率 × 预估结算金额，分平台）
         − 达人佣金（商务订单自动匹配，仅预估结算订单产生）
         − 广告费（月消耗表「汇总」按电商平台汇总）
```

- 预估结算金额：订单「销售金额」在判定为预估结算后求和；退款订单的收入与产品成本按 0 计，也不参与包装费/运费/运费险；
- 天猫没有名为「销售金额」的列，取提成用 Sheet 的「报表买家实付金额」（报表口径，已扣除退款）；
- 毛利率 = 粗算毛利 / 预估结算金额；
- 产品成本费比 = 产品成本 / 预估结算金额（通常应在 30% 以上，低于参考线在面板中黄色提示）；
- 退款比例 = 退款销售额 / (预估结算金额 + 退款销售额)；
- 以上两项比率同时导出到「平台汇总」Sheet；
- 默认排除刷单/测试订单（抖音/京东/拼多多「是否刷单」、视频号「刷单产品」等），面板可开关；
- 月消耗表中没有订单源的平台默认不并入总毛利，可开关（当前 7 个平台均有订单源）。

## 包装费 / 运费 / 运费险的两种算法与「件」的口径

包装费、运费、运费险三项均**分平台独立设置**，每项在面板 Ⅲ「分平台费率」中通过下拉框选择算法：

1. **按件单价**（默认）：总额 = 单价（元/件）× 结算商品数量；
2. **按总额**：直接填写该项费用的总额（元），不再乘数量。

默认排序下每平台 3 项、7 个平台共 21 个算法下拉；某个平台切换算法不会影响其他平台。Excel 导出的「计算参数」Sheet 会记录每个平台每项费用采用的算法与取值。

**「件」= 结算商品数量**，不是订单数，也不是 SKU 种数：取各平台订单源中「商品数量」字段，在判定为「预估结算」的订单行上求和，退款订单不计。各平台实际取用的字段：

| 平台 | 商品数量字段 |
| --- | --- |
| 快手 | 成交数量 |
| 视频号 | 商品数量 |
| 抖音 | 商品数量 |
| 天猫 | 购买数量 |
| 拼多多 | 商品数量(件) |
| 京东 | 订购数量 |
| 小红书 | SKU件数 |

面板 Ⅲ「计费口径」卡片会展示每个平台的结算商品数量与来源字段，便于核对；产品成本、包装费/运费/运费险（按件模式）都基于同一「结算商品数量」口径。

## 缺失成本批量补录（Excel）

面板 Ⅲ「缺失成本补录」支持逐行填写，也支持 Excel 批量补录：

1. **下载补录模板**：按当前缺失成本 SKU 生成，关键列沿用原成本表格式——A 款式编码、B 商品编码（SKU）、C 商品名、D 成本价（括号内标注原成本表列名）；E 建议成本价、F 平台、G 结算件数、H 备注 仅作参考，可忽略或删除。
2. **填写**：只需在 D 列填入每个 SKU 的成本价（元），保存为 .xlsx；没有成本的 SKU 留空即可。
3. **上传**：点「Excel 批量补录」选择文件，或直接把 .xlsx 拖入该卡片。系统自动识别表头，兼容「商品编码 / 商品名称 / 成本价（成本单价 / 进价等）」常见列名；也兼容直接整理成原成本表格式（款式编码、商品编码、商品名、成本列）的文件，多余列会被忽略。
4. **导入结果**：卡片顶部会显示导入 SKU 数、解析行数、被忽略的未知 SKU / 无效成本行与提示；导入先进入当前参数草稿并实时预览毛利（缺失列表同步减少），确认后需点面板右上角「提交并保存」才写入 `data/config.json`，也可以「撤销修改」放弃。
5. **约束**：仅支持 .xlsx（不支持 .xls / CSV），文件 ≤ 6MB；SKU 需已出现在订单或原成本表中，否则按未知 SKU 忽略；同一 SKU 多行时取最后一行成本价；补录成本优先于成本表价格，并会导出到 Excel 的「成本补录」Sheet 便于核对。


## 达人佣金（商务订单）

- 自动读取 `excel/商务订单`（当前目录 `9月份商务订单`）下所有 xlsx，按文件名/路径识别平台；
- 快手/视频号：使用商务订单明细中的佣金列（行级，按 `订单号 + SKU` 匹配订单行）；
- 抖音：使用「精选联盟订单 → 达人订单」的 `预估佣金支出`（订单级，按 `订单id` 匹配主订单编号或子订单编号）；
- **只有判定为「预估结算」的订单才产生达人佣金**：匹配到的订单若为退款订单，佣金计 0；匹配不到订单的佣金记录也计 0，并在面板中提示；
- 佣金不提供手工填写：全部来自商务订单数据。

## 状态判定规则（可在面板 Ⅰ 拖拽覆盖）

按「订单状态 × 售后状态」组合推理，优先级：

1. 订单状态为关闭类（`交易关闭`、`已取消`、`已关闭`）→ **退款订单**
2. 售后状态为换货/补发（`换货`、`补发`、`重新邮寄`）→ **预估结算**
3. 售后状态为退款已关闭类（`退款关闭`、`没有申请退款`、`用户取消申请`、`售后关闭`、`售后取消`、`商家拒绝退款`）→ **预估结算**
4. 售后进行中（`待商家收货`、`待买家退货`、`售后处理中`、`售后协商中` 等）→ **退款订单**
5. 已退款/退货完成（`退款成功`、`退款完成`、`退货退款完成`、`售后完成`）→ **退款订单**
6. 订单状态本身含退款/退货结果（如拼多多「已发货，退款成功」）→ **退款订单**
7. 无售后或正常状态（`交易成功`、`已完成`、`已发货`、`完成`、`已签收` 等）→ **预估结算**
8. 未识别的新状态 → 默认预估结算并在面板标黄「待确认」

人工拖拽结果写入 `data/config.json` 的 `statusOverrides`，优先于自动规则，刷新后仍然生效；「恢复自动判定」可清除。

## 面板

- **Ⅰ 状态判定关系**：按平台展示状态组合卡片，分「预估结算 / 退款订单」两列；拖拽卡片（或卡片右下角按钮、聚焦后空格键）即可改判，金额与毛利实时重算并持久化。
- **Ⅱ 毛利结构**：瀑布图逐项扣减 + 平台对比表（新增「产品成本费比」「退款比例」，支持合计/分平台切换）。
  - 产品成本费比 = 产品成本 / 预估结算金额，表头与单元格带 **≥30% 参考线**，低于 30% 时黄色高亮（该比值通常应在 30% 以上）；
  - 退款比例 = 退款销售额 / (预估结算金额 + 退款销售额)；
  - 平台对比表支持**自定义字段排序**：可直接拖拽表头，或点「字段排序」面板用 ↑/↓ 调整，顺序持久化到配置，并提供「重置默认」；平台列固定在最左。
- **Ⅲ 人工填写与参数**：上半部分为「计费口径」说明（明确「件」= 结算商品数量及各平台来源字段），下半部分为**分平台费率**：包装费/运费/运费险均支持「按件单价 / 按总额」下拉切换（各平台独立），另有平台技术服务费率、商业保险费率、缺失成本补录（支持下载模板 / 拖入 Excel 批量补录）、商务订单达人佣金明细（自动匹配，无手工输入）、广告费明细与数据文件状态。
  - 参数改为**草稿 + 显式提交**交互：填写后立即按草稿调用预览接口实时重算毛利（不写配置）；面板右上角提供「提交并保存」「撤销修改」「恢复默认参数」，页面底部还有「有 N 项修改未保存」悬浮操作条；
  - 提交后参数写入 `data/config.json` 并全量重算；支持 **Ctrl+S / ⌘+S 快捷提交**；有未保存修改时「刷新数据」会提示先提交或撤销，关闭页面前也会弹出浏览器确认；
  - 表头排序属于视图偏好，仍即时保存，不会提交草稿参数。

人工填写参数只有在点击「提交并保存」后才写入配置；编辑过程中通过 `POST /api/config/preview` 只读预览重算（服务端带结果缓存），顶部提示条汇总口径相关警告。

## 假设与限制

1. 商务订单仅覆盖快手、视频号、抖音；天猫、拼多多、京东、小红书暂无佣金数据，达人佣金按 0 计并在面板提示。
2. 达人佣金取「预估佣金支出 / 预估推广佣金 / 带货费用」；部分佣金记录对应的订单不在订单源导出范围内（如筛选口径不同），匹配不到时计 0 并在面板提示。
3. 成本表 8 月成本用于 9 月订单（按现有数据）；151 个 SKU 在成本表缺失（涉及结算 10,345 件），可逐行或通过 Excel 批量补录。
4. 平台技术服务费、商业保险费一律取面板人工输入的百分比，源表中的技术服务费/运费险列仅作参考，不参与公式。
5. 单机单用户本地应用，无登录与数据库；配置与缓存都在 `data/`，删除后会自动重建。解析逻辑变更时通过缓存版本号自动失效旧缓存。
6. 订单源除目标 Sheet 外的工作表、`回收状态`、`物流与否` 等字段不参与计算。
